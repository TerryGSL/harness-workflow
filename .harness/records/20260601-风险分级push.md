## Changed & Why（改了什么/为什么）
- scripts/gate-lib.sh：加 RISK_DEP/SCHEMA/CI/DOCS_ONLY/ACK 正则，规则单一来源(pre-push 与 ci-gate 共用，永不漂移)。
- scripts/classify-risk.sh（新）：纯规则无 LLM。HIGH=密钥/改依赖/改 db schema·migration/改 CI；LOW=全文档；MEDIUM=其余。range 取法支持有 base / 无 base(看单 commit)。
- githooks/pre-push：循环里用 push 的精确 refs 算 range(已有分支=remote_sha；新分支=最老新 commit 的父)，聚合最高风险；HIGH 在测试前问一次(三态：HARNESS_CONFIRM/tty/非交互放行+提示)。测试失败仍硬 block，不被 risk override。
- scripts/ci-gate.sh：HIGH 增量推送必须有 commit 带 Risk-Ack: 留痕（CI 不能问人），仅在有真实 BASE 时启用(首推豁免)。

## Decisions（非显然取舍）
- HIGH 触发器**故意不收「文件数 > N」**：纯文件数不是危险信号，频繁触发会让 HIGH 确认沦为无脑 y，护栏变剧场(codex 核心告诫)。HIGH 只收内容高危：密钥/依赖/schema/CI。
- ci-gate 的 risk 门**仅在有真实 BASE(增量推送)时启用**：首次推送整仓必含 CI/依赖文件，评 HIGH 无意义且卡建仓。pre-push 端是 ask(非 block)故不豁免。
- 测试失败保持**硬 block，绝不给 HIGH 人工 override**——给失败测试开后门 = 护栏变剧场(codex)。
- **#2 审稿 4 硬门不新建代码**：codex 确认唯三可机械化(bug 有测试 / feature 有 Reviewed-by / record 同 commit 绑定)在现有 verify-evidence + 沉淀门已全具备；Grounding/Coverage/Knowledge 不可机械验证，当强制 prose 会漂，不收。
- **#3 冲突 judge / #5 XL 拆轮 skip**：单人用不上 judge；让 state.json 持有未来工作 = 重造死状态。#4 自治边界只把 push 相关部分通过本 record 的 #1 吸收，不建独立框架。
